# Bascule API directe (api.duello.fr) — état au 27/08/2026

Migration terminée. Le but était de servir l'API Duello en direct
(`https://api.duello.fr/api`) au lieu du relais Cloudflare
(`https://duello-api-relay.duello.workers.dev/api`), en profitant d'une IP
publique **statique** + d'un **domaine** (base : IP statique donnée par le VPS,
contrairement au tunnel indispensable sur un VPS à IP éphémère).

## ☑️ Fait

**Serveur (Azure, VM `duello-prod-vm`)**
- DNS Cloudflare : `A api.duello.fr → 172.182.240.65` (mode « DNS only », pas de proxy).
- nginx reverse proxy : `api.duello.fr` (80/443) → `http://127.0.0.1:8891`
  (même origine que le tunner) ; bind 443 sur l'IP **privée** de la VM.
- Certificat Let's Encrypt posé via `certbot --nginx` (valide jusqu'au 25/11/2026,
  renouvellement automatique par le timer/systemd).
- NSG Azure : règles entrantes TCP 80 et 443 ajoutées (Source Any).
- Vérifié depuis l'extérieur : `https://api.duello.fr/` → 404 (même origine que le
  relais), `http://api.duello.fr/` → 301 HTTPS, parité des routes avec le relay.

**App (projet Duello, VPS Google, conteneur `duello-server`)**
- `config/cloudflare-tunnel.json` : `hostname` + `apiUrl` → `api.duello.fr`
  (source de vérité release, lue par `src/config/platform.ts`).
- `eas.json` : `EXPO_PUBLIC_DUELLO_API_URL=https://api.duello.fr/api` (3 profils).
- Porte de build validée : `node scripts/tunnel.mjs check` → *URL fixe :
  https://api.duello.fr/api*.
- Publication OTA production publiée : build `1.0.16`, update group
  `35a9bbe0-6822-4713-b9e2-73c99123b6e1`, message « Bascule-API-vers-api.duello.fr ».
  Dashboard : https://expo.dev/accounts/liquidplus/projects/duello-mobile/updates/35a9...
- Sauvegardes créées pour rollback :
  `eas.json.bak-api-direct-*` et `config/cloudflare-tunnel.json.bak-api-direct-*`.

## ⚠️ Reste à faire / à connaître

1. **Conteneur `duello-server`** : il tourne toujours en mode relay (URL workers.dev).
   Il n'a PAS été redémarré (sinon crash-loop au démarrage, cf. README). Une fois les
   anciennes builds écoulées, prévoir soit de le neutraliser (`scripts/tunnel.mjs`),
   soit de l'arrêter proprement.
2. **Limite mémoire du conteneur relevée à 3 Go** (`docker update --memory 3g`) pour
   permettre le bundling d'eas update ; la ligne `mem_limit: 1g` du compose
   `deploy/duello/compose.yaml` redeviendra effective au prochain `up` (à ré-ajuster
   si on veut republier : passer à ≥ 3 Go, sinon eas-roch-pat-server bloquera).
3. **Ne PAS relancer `npm run tunnel:setup`** : il réécrit la config vers l'URL
   workers.dev (annule la bascule).
4. **Publication normale** : utiliser `EAS_NO_VCS=1` à l'intérieur du conteneur en
   user `cst`, et éviter de lancer eas en root (pollue caches npm/expo).

## Rollback

- Serveur : `rm /etc/nginx/sites-enabled/api.duello.fr` puis `nginx -t && systemctl reload nginx`,
  et au besoin `certbot delete --cert-name api.duello.fr`.
- App : restaurer les `.bak-api-direct-*` puis rebuilder/re-public.
